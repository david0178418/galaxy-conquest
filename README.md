# Galaxy Conquest

A touch-first, single-player RTS feel prototype based on the [initial design](docs/game-design-v0.1.md). Bun serves and bundles the HTML/TypeScript/CSS directly; ECSpresso 0.24.1 owns planets, individual ships/transports, production, movement, combat, AI, and victory. No Vite or extra server framework.

```sh
bun install --frozen-lockfile
bun run dev
```

Developer timing and a reusable crowded fixture are documented in [Performance diagnostics](docs/performance-diagnostics.md).

Open http://localhost:3000. `bun run check` runs strict TypeScript checks, simulation tests, and a production build into `dist/`.

GitHub Pages publishes the production build at https://david0178418.github.io/galaxy-conquest/. The [deployment workflow](.github/workflows/deploy.yml) runs checks, builds, and deploys on pushes to `main`; it can also be run manually from the Actions tab on `main`. Repository Settings → Pages must use **GitHub Actions** as the build source. Bundled asset URLs are relative, so the same build works under `/galaxy-conquest/` and at a domain root.

The production build is an installable PWA. Open the standalone HTTPS site and use your browser's **Install app** command; on iPhone/iPad, use Safari's **Share → Add to Home Screen**. It opens in its own window using the existing GC icon. Installation availability depends on the browser; embedded player cards should be opened as the standalone site first.

After the first online visit finishes caching, the game can reopen and play offline, including local profiles and saves. New releases download in the background and activate after all game windows/tabs close; an ongoing conquest is never reloaded automatically. Saves remain in IndexedDB and retain the browser/site storage limits described below. Workbox generates the offline cache from build assets; source maps and the social poster are excluded. PWA registration is production-only, so `bun run dev` does not install a worker. Serve `dist/` over localhost or HTTPS to test installation/offline behavior.

That Pages URL is also an X player card. On desktop web, opening the card loads this game in the post. Share the exact URL, including the trailing slash, and only after this version is deployed. X keeps the card it first fetched for a URL. The poster is [assets/x-card.jpg](assets/x-card.jpg), published as `x-card.jpg`. GitHub Pages does not send `X-Frame-Options`, which is what lets X frame the page. A host that denies framing will show only the poster.

## Campaign development preview

Open the game with `?campaign=1` to enable **New campaign preview** and **Continue campaign** on the title screen. The ordinary entry remains skirmish while the campaign loop and presentation await owner acceptance. Each local profile has independent campaign and skirmish saves; replacing one leaves the other intact.

The preview starts with two systems of three planets, one system per faction. Select your system, contribute planetary points to an expedition, and choose **End turn**. The rival commits at most one expedition per turn using half its available source points. Travel uses distance and configurable speed; arrivals resolve in order, with separate battles and no mid-battle reinforcements. Friendly arrivals replenish the most depleted destination planets first; surplus is discarded.

At an encounter, edit your planetary defenses or divide your expedition among beachheads. Troops cost 1 point, ships 6, and defense platforms 5. All invasion forces enter from one off-screen edge based on travel direction, without a local source or initial recall order. Normal local dispatch and recall remain available. Combat production continues; the galaxy stays frozen. A faction loses an encounter when it has neither a planet nor a loaded troop transport. Remaining ships and empty transports are cleanup losses. There is no withdrawal or automatic battle time limit.

Use **Return to galaxy** after an encounter to apply ownership and continue the turn. Tactical survivors and produced units do not become campaign points. Spending remains spent after defeat. At each completed galaxy turn, held planets grow capacity by 2% of baseline, capped at +20%, then recover 10% of current maximum. Capture halves accumulated development, including brief captures and recaptures; capture turns recover but do not grow. Absolute depletion persists even above a reduced maximum. Campaign victory requires the rival to have neither planets nor unresolved expeditions.

Galaxy actions, valid allocation drafts, and ongoing battles save to the campaign slot. Continue restores battles paused without reseeding forces or spending twice. Rules are configurable in `src/campaign-state.ts`; setup costs are in `src/campaign-setup.ts`. The preview uses the existing browser storage limits and profile isolation.

## Skirmish and local profiles

The title screen offers up to 10 local profiles. On first use, create **Player** or enter another name. Each profile has one ongoing skirmish in addition to its separate campaign slot: **Continue** restores its saved map and game state paused, and **New game** starts over after confirmation. Rename keeps progress; deleting a profile requires confirmation and removes only that profile. Choose **Save** at any time or rely on periodic autosaves, including while paused. Save status and failures appear in the game header and game menu.

Starting a new conquest or replacing the current map requires confirmation when it would replace progress. From **New game**, choose **Small** (12 worlds), **Medium** (18), or **Large** (30), inspect the preview, and use **Generate another map** to reroll it. **Start conquest** launches that exact layout with one world and three ships per side. Generated worlds have mirrored positions and resources for equal expansion opportunities, with at least 216 units between centers. **Restart map** replays the same layout.

Profiles and conquests use IndexedDB in the current browser and site. They do not sync between devices, browsers, hosting origins, or embedded and standalone versions. Clearing site data or browser storage eviction can remove them. Embedded browsers may block or partition storage; open the standalone game if saves are unavailable. There is no account, cloud backup, or export/import.

Save validation has format safety bounds independent of gameplay tuning: at most 100,000 troops per planet or cargo units per transport; production-rate values up to 10,000 and production progress below 10,000; map dimensions up to 10,000; unit positions within ±20,000; and planet radii up to 1,000. A save outside those bounds cannot be continued; validation leaves the stored profile data unchanged.

The star map fills the viewport. Drag to pan; scroll up to zoom in and down to zoom out around the pointer, or pinch to zoom on touchscreens. Horizontal scrolling pans sideways. Use Fullscreen in the game menu to enter or leave fullscreen where supported. Focus the map and use arrow keys to pan with a keyboard. Selecting a planet opens a fixed command panel on the right (bottom on phones); rival and neutral worlds show their information. The game menu contains fullscreen, restart, new game, profiles, scenarios, pace, save status, and help. The compact top bar keeps planet counts, time, Orders, Save, Pause, and the menu in view; phones omit the title to preserve map space. Production controls appear only when you select a world you own.

Tap or left-click a blue planet to select it. On touch, hold a destination for 500 ms to send 50% of the selected sources’ troops and ships; with a mouse, right-click the destination. A short tap or left click only changes selection. Dragging, pinching, or cancelling a touch cancels a pending hold. Change the send amount or choose ships/troops only in the command panel. Production buttons change the selected planets; defense platforms never travel. Multi-select gathers several sources; finish selection before holding or right-clicking a destination. Tap a selected source again or use Clear selection to deselect. Tap your blue orbital presence over an enemy world to redirect blockading ships.

Troops capture surfaces. Ships and immobile defense platforms fight in orbit. Traveling ships trade fire with hostile traveling ships and transports within 48 units, stopping in place while engaged and resuming their original destinations once combat clears. Transports have no weapons: they take that damage and continue along their flight paths. Orbiting ships, transports, and defense platforms do not participate in passing combat; normal orbital combat applies after arrival. A passer does not join an orbit, change a blockade, or block a landing. Automatic disposable transports carry up to 10 troops each and wait for hostile orbital resistance to clear before landing. Escorts absorb incoming fire first; exposed transports can die with their cargo. Orbital control alone never captures the surface. A dashed hostile ring means blockade, preventing surface departures while production continues. A solid ring marks hostile presence before complete control. Newly produced ships and defense platforms immediately fight blockaders. Ground combat uses immediate numerical attrition; a surviving attacking troop is required to capture. Partial production is discarded when switching.

The **Prototype lab** contains a normal AI skirmish, an established blockade, and a defended invasion. Labs start with AI disabled; enable it when useful. Restart resets the scenario; pace changes persist. Pause freezes movement, production, combat, and AI while keeping map navigation, selection, orders, and production changes available. Orders allocate units immediately, so repeated sends use the remaining stock; movement and production progress continue on resume, without catching up paused time. Open **Orders** beside Pause to view active dispatches. The drawer shares the command panel’s space and filters incoming, outgoing, and returning routes to the selected planet (or selected sources). **Show all** keeps the planet selection while showing every route; changing the selection restores automatic filtering. Select an order row to highlight its route without changing the selected planet. **Cancel launch** releases a paused dispatch’s reserved ships and troops before departure. **Recall** turns surviving escorts and loaded transports around at their current positions and sends each back to its own departure world; recalling during pause sets the course but movement waits for resume. Returning orders remain visible until arrival. Waiting transports and their escorts can be recalled before landing; completed arrivals leave the drawer. If a departure world changes hands, normal arrival/combat rules apply there. Switching tabs pauses simulation automatically. Win by taking every rival planet.

Tune rates, capacity, costs, movement, and combat in [src/config.ts](src/config.ts). Map generation and the fixed lab layout are in [src/maps.ts](src/maps.ts); repeatable scenario setups are in [src/game.ts](src/game.ts). Both sides use the same production and combat rules. Neutral worlds do not produce. The deterministic simulation uses a 0.05-second timestep. Each moving capital ship and transport is its own ECS entity; there is no fleet entity or transport inventory.

Normal games use generated maps across 1040 × 1080 (Small), 1200 × 1320 (Medium), or 1560 × 1716 (Large) world-unit areas, basic AI, and instant ground attrition. The prototype lab retains its fixed eighteen-world map across a 1200 × 1320 area. Planet centers are at least 216 units apart. Both sides start with one world; all remaining worlds are neutral. Pan and zoom to inspect the expanded map. There is no networking, controller support, audio, cloud sync, or arbitrary mid-flight retargeting (recall to the departure world is supported). The lab reports first player capture, player orders, total captures, and combined transport/cargo losses. Counts on surfaces are troops; ◆ counts are orbital ships and ✣ counts are defense platforms (rounded up while damaged). Each platform also appears as an owner-colored turret on a slowly turning outer orbit; its motion pauses with the simulation.

Simulation checks cover the opening capture, production switching, transport exposure and grace time, escorted invasions, blockade/reinforcement/redeployment, pause, cancellation/recall, multi-source sends, AI expansion, simultaneous combat, and victory. Physical-device touch comfort, combat readability, balance, and match feel require playtesting.
